## 3. 三个核心文件逐行解读

### 3.1 `shopify.app.toml` —— App 的身份证

```toml
client_id = ""

[access_scopes]
scopes = "write_products"          # ← 你要的权限

[webhooks]
api_version = "2025-10"            # ← API 版本

  [[webhooks.subscriptions]]
  uri = "/webhooks/app/uninstalled"
  topics = ["app/uninstalled"]

  [[webhooks.subscriptions]]
  topics = ["app/scopes_update"]
  uri = "/webhooks/app/scopes_update"
```

**要点**：
- **改 `scopes` 后必须重新授权**。dev 环境下 CLI 会提示你重新安装。
- Webhook 在这里**声明式配置**，CLI 部署时自动注册。不需要写代码调 API 注册。
- 模板还注释掉了 **GDPR 合规 webhook**（`customers/data_request`、`customers/redact`、`shop/redact`）——**公开发布的 App 必须打开这三个**，是审核硬性要求。

```toml
# 上架前必须取消注释并实现
[[webhooks.subscriptions]]
uri = "/webhooks/customers/data_request"
compliance_topics = ["customers/data_request"]

[[webhooks.subscriptions]]
uri = "/webhooks/customers/redact"
compliance_topics = ["customers/redact"]

[[webhooks.subscriptions]]
uri = "/webhooks/shop/redact"
compliance_topics = ["shop/redact"]
```

模板还展示了 **webhook 过滤器**（减少无用推送）：

```toml
[[webhooks.subscriptions]]
topics = ["products/update"]
uri = "/webhooks/products/update"
filter = "variants.price:>=10.00"     # 只推价格 >= 10 的商品更新
```

### 3.2 `app/shopify.server.ts` —— 服务端初始化

```ts
import "@shopify/shopify-app-react-router/adapters/node";
import { ApiVersion, AppDistribution, shopifyApp } from "@shopify/shopify-app-react-router/server";
import { PrismaSessionStorage } from "@shopify/shopify-app-session-storage-prisma";
import prisma from "./db.server";

const shopify = shopifyApp({
  apiKey: process.env.SHOPIFY_API_KEY,
  apiSecretKey: process.env.SHOPIFY_API_SECRET || "",
  apiVersion: ApiVersion.October25,
  scopes: process.env.SCOPES?.split(","),
  appUrl: process.env.SHOPIFY_APP_URL || "",
  authPathPrefix: "/auth",
  sessionStorage: new PrismaSessionStorage(prisma),
  distribution: AppDistribution.AppStore,
  future: { expiringOfflineAccessTokens: true },
  ...(process.env.SHOP_CUSTOM_DOMAIN ? { customShopDomains: [process.env.SHOP_CUSTOM_DOMAIN] } : {}),
});

export default shopify;
export const apiVersion = ApiVersion.October25;
export const addDocumentResponseHeaders = shopify.addDocumentResponseHeaders;
export const authenticate = shopify.authenticate;
export const unauthenticated = shopify.unauthenticated;
export const login = shopify.login;
export const registerWebhooks = shopify.registerWebhooks;
export const sessionStorage = shopify.sessionStorage;
```

**逐项含义**：

| 配置 | 作用 | 注意 |
|---|---|---|
| `apiKey` / `apiSecretKey` | App 的身份凭证 | secret **绝不能进浏览器** |
| `apiVersion` | 用哪个版本的 Admin API | 模板锁 `October25`。季度发版，每版支持 12 个月 |
| `scopes` | 权限范围 | 从环境变量读，和 toml 保持一致 |
| `sessionStorage` | 存商家 access token | 默认 SQLite，**生产必须换 Postgres** |
| `distribution` | 分发方式 | `AppStore`（公开）/ `SingleMerchant`（私有） |
| `future.expiringOfflineAccessTokens` | 启用会过期的 offline token | 未来会成为默认，提前适配 |

**导出的 `authenticate` 是你用得最多的东西**：

```ts
authenticate.admin(request)      // 后台页面鉴权，返回 { admin, session }
authenticate.webhook(request)    // webhook 验签，返回 { topic, shop, payload }
authenticate.public.appProxy(request)   // App proxy 请求
```

### 3.3 `app/routes/app.tsx` —— 布局与守卫

```tsx
export const loader = async ({ request }: LoaderFunctionArgs) => {
  await authenticate.admin(request);          // ① 鉴权守卫
  return { apiKey: process.env.SHOPIFY_API_KEY || "" };
};

export default function App() {
  const { apiKey } = useLoaderData<typeof loader>();
  return (
    <AppProvider embedded apiKey={apiKey}>    {/* ② 提供 App Bridge context */}
      <s-app-nav>                              {/* ③ 后台左侧导航 */}
        <s-link href="/app">Home</s-link>
        <s-link href="/app/additional">Additional page</s-link>
      </s-app-nav>
      <Outlet />                               {/* ④ 子路由 */}
    </AppProvider>
  );
}

export function ErrorBoundary() {
  return boundary.error(useRouteError());      // ⑤ 错误 + CSP header
}

export const headers: HeadersFunction = (headersArgs) => boundary.headers(headersArgs);
```

**为什么鉴权只写在这里就够了**：`/app/*` 下所有路由都是 `app.tsx` 的子路由，父 loader 一定先跑。一处守卫，全线受保护。

### 4.2 页面骨架

```jsx
<s-page heading="商品管理">
  <s-button slot="primary-action" variant="primary">新建商品</s-button>

  <s-section heading="全部商品">
    <s-stack direction="block" gap="base">
      {/* 主内容 */}
    </s-stack>
  </s-section>

  <s-section slot="aside" heading="筛选">
    {/* 右侧栏 */}
  </s-section>
</s-page>
```

**`slot` 是 Web Components 的内容分发机制**，等价于 React 里"把组件当 props 传"。`slot="primary-action"` 会把按钮放进页面标题栏右侧。

### 4.4 ⚠️ 两个必踩的坑

#### 坑一：布尔属性

```jsx
// ❌ React 18 会渲染成 loading="false"，
//    但 HTML 里"attribute 存在即为真"，可能导致按钮一直转圈
<s-button loading={isLoading}>保存</s-button>

// ✅ 官方模板的写法：条件展开，false 时干脆不传
<s-button {...(isLoading ? { loading: true } : {})}>保存</s-button>
```

**这段是从官方模板一字不差抄来的**，不是作者手抖。

#### 坑二：复杂属性传不进去

```jsx
// ⚠️ React 18 对自定义元素会把值转成字符串塞进 attribute
<s-select options={[{ label: 'A', value: 'a' }]} />   // → "[object Object]"

// ✅ 用 ref 直接赋 property
function MySelect({ options }) {
  const ref = useRef<HTMLElement>(null);
  useEffect(() => {
    if (ref.current) (ref.current as any).options = options;
  }, [options]);
  return <s-select ref={ref} label="商品" />;
}
```

**背景**：React 19 改进了自定义元素的属性处理（优先尝试 property），但**模板还在 React 18.3.1**。

详细原理见 [02 号文档 D1](02-React知识补充清单.md)。

## 5. 第一个真实功能：带分页的商品列表

把 loader + GraphQL + URL 状态 + Polaris WC 串起来。

### `app/routes/app.products.tsx`

```tsx
import type { LoaderFunctionArgs } from "react-router";
import { useLoaderData, useSearchParams, useNavigation } from "react-router";
import { authenticate } from "../shopify.server";

export const loader = async ({ request }: LoaderFunctionArgs) => {
  const { admin } = await authenticate.admin(request);

  const url = new URL(request.url);
  const cursor = url.searchParams.get("cursor");
  const query = url.searchParams.get("q") ?? "";

  const response = await admin.graphql(
    `#graphql
      query GetProducts($first: Int!, $after: String, $query: String) {
        products(first: $first, after: $after, query: $query) {
          nodes {
            id
            title
            status
            totalInventory
            featuredImage { url altText }
          }
          pageInfo { hasNextPage hasPreviousPage endCursor startCursor }
        }
      }`,
    {
      variables: {
        first: 20,
        after: cursor,
        query: query ? `title:*${query}*` : undefined,
      },
    }
  );

  const json = await response.json();

  if (json.errors?.length) {
    throw new Response(json.errors[0].message, { status: 500 });
  }

  return { products: json.data.products };
};

export default function ProductsPage() {
  const { products } = useLoaderData<typeof loader>();
  const [searchParams, setSearchParams] = useSearchParams();
  const navigation = useNavigation();
  const isLoading = navigation.state === "loading";

  const nextPage = () => {
    setSearchParams((prev) => {
      prev.set("cursor", products.pageInfo.endCursor);
      return prev;
    });
  };

  return (
    <s-page heading="商品">
      <s-section>
        <s-search-field
          label="搜索商品"
          value={searchParams.get("q") ?? ""}
          onInput={(e: any) => {
            setSearchParams((prev) => {
              prev.set("q", e.target.value);
              prev.delete("cursor");        // 换筛选条件时重置分页
              return prev;
            });
          }}
        />

        {isLoading && <s-spinner />}

        {!isLoading && products.nodes.length === 0 && (
          <s-banner tone="info">没有找到商品</s-banner>
        )}

        <s-stack direction="block" gap="base">
          {products.nodes.map((p: any) => (
            <s-box key={p.id} padding="base" borderWidth="base" borderRadius="base">
              <s-stack direction="inline" gap="base">
                {p.featuredImage && (
                  <s-thumbnail src={p.featuredImage.url} alt={p.featuredImage.altText ?? ""} />
                )}
                <s-stack direction="block">
                  <s-heading>{p.title}</s-heading>
                  <s-badge tone={p.status === "ACTIVE" ? "success" : "neutral"}>
                    {p.status}
                  </s-badge>
                  <s-text>库存：{p.totalInventory}</s-text>
                </s-stack>
              </s-stack>
            </s-box>
          ))}
        </s-stack>

        <s-button
          onClick={nextPage}
          {...(products.pageInfo.hasNextPage ? {} : { disabled: true })}
        >
          下一页
        </s-button>
      </s-section>
    </s-page>
  );
}
```

**这段代码演示了 6 个要点**：
1. loader 里鉴权 + 调 Admin GraphQL
2. 分页游标存在 **URL** 里（可刷新、可分享）
3. 搜索词也在 URL 里
4. loading 状态从 `useNavigation()` 拿，不用 useState
5. 处理了空状态
6. 布尔属性用条件展开写法

**记得**：把导航链接加进 `app.tsx` 的 `<s-app-nav>`，否则商家找不到这个页面。

## 6. Webhook 处理

```tsx
// app/routes/webhooks.app.uninstalled.tsx
import type { ActionFunctionArgs } from "react-router";
import { authenticate } from "../shopify.server";
import db from "../db.server";

export const action = async ({ request }: ActionFunctionArgs) => {
  const { shop, topic, session } = await authenticate.webhook(request);
  //     ↑ 这一行已经完成了 HMAC 验签，失败会抛 401

  console.log(`收到 ${topic} webhook：${shop}`);

  // ⚠️ 幂等：webhook 是"至少一次"投递，可能重复
  if (session) {
    await db.session.deleteMany({ where: { shop } });
  }

  return new Response();     // 必须快速返回 200，否则 Shopify 会重试
};
```

**三条铁律**：
1. **必须验签**——`authenticate.webhook()` 帮你做了，别自己解析 body 绕过它
2. **必须幂等**——同一个事件可能推多次，处理逻辑要能重复执行
3. **必须快速返回**——重活扔进队列异步做，Shopify 有超时限制（超时会重试，加剧重复）

## 7. App Bridge 常用能力

```tsx
import { useAppBridge } from "@shopify/app-bridge-react";

function MyComponent() {
  const shopify = useAppBridge();

  // Toast 提示
  shopify.toast.show("保存成功");
  shopify.toast.show("保存失败", { isError: true });

  // 跳转到后台的某个资源（模板里的真实用法）
  shopify.intents.invoke?.("edit:shopify/Product", { value: productId });
}
```

**Toast 的正确用法**（这是模板里唯一的 useEffect，也是 useEffect 的正当场景）：

```tsx
const shopify = useAppBridge();
const fetcher = useFetcher<typeof action>();
const productId = fetcher.data?.product?.id;

useEffect(() => {
  if (productId) {
    shopify.toast.show("Product created");
  }
}, [productId, shopify]);
```

**为什么这里必须用 effect**：`shopify.toast` 是跑在 iframe 外层、不受 React 管辖的宿主系统。"服务端返回新数据 → 通知外部系统"是 useEffect 的教科书用法。

## 8. App 线常见卡点

| 症状 | 原因 | 解决 |
|---|---|---|
| 后台里 App 页面白屏 | CSP header 不对 | 检查 `boundary.headers` 有没有导出 |
| `authenticate.admin` 报 401 | session token 过期或 scopes 变了 | 重新安装 App |
| 改了 scopes 没生效 | 需要重新授权 | `shopify app deploy` 后重装 |
| GraphQL 返回 200 但没数据 | 没查 `userErrors` | 加上并检查 |
| GraphQL 报 `THROTTLED` | 限流 | 减小 `first`、加指数退避重试 |
| `<s-xxx>` 标签 TS 报错 | 缺类型 | 确认 `@shopify/polaris-types` 在 devDependencies |
| 组件属性传不进去 | 自定义元素 attribute 限制 | 用 ref 赋 property |
| 按钮一直 loading | 布尔属性坑 | 用条件展开写法 |
| 隧道地址变了 App 打不开 | dev 隧道每次重启会变 | 用 `shopify app dev` 自动更新配置 |
| 生产环境 session 丢失 | SQLite 在多实例下不共享 | 换 Postgres |

## 10. 与 App 线的关键差异

| | App 线 | Hydrogen 线 |
|---|---|---|
| API | Admin API（管理数据） | **Storefront API**（面向买家） |
| 鉴权 | OAuth + session token | **公开 token**（可在浏览器用） |
| 客户端调用 | ❌ 只能服务端 | ✅ 可以（有专门的公开 token） |
| UI | Polaris Web Components | **完全自己写**（无预设 UI 库） |
| 运行时 | Node | **Workers**（Oxygen） |
| 数据库 | Prisma | 通常不需要 |
| 部署 | 自己找主机 | Oxygen（免费） |

### ⚠️ Workers 运行时限制（Hydrogen 最大的隐性门槛）

依赖 `@shopify/oxygen-workers-types`，意味着**不是完整 Node 环境**：

```
❌ 用不了：fs、path、child_process、大部分 Node 内置模块
❌ 很多 npm 包会炸（尤其是依赖 Node 内置模块的）
✅ 能用：fetch、Request、Response、URL、crypto.subtle、Web Streams
```

**选包前先确认标注了 "edge compatible" 或 "workers compatible"。**

## 11. 数据获取

```tsx
export async function loader({ context, params }: LoaderFunctionArgs) {
  const { storefront } = context;

  const { product } = await storefront.query(PRODUCT_QUERY, {
    variables: { handle: params.handle },
    cache: storefront.CacheLong(),       // ← 缓存策略
  });

  if (!product) throw new Response("Not found", { status: 404 });

  return { product };
}

const PRODUCT_QUERY = `#graphql
  query Product($handle: String!) {
    product(handle: $handle) {
      id
      title
      descriptionHtml
      variants(first: 10) {
        nodes { id title availableForSale price { amount currencyCode } }
      }
    }
  }
`;
```

### 缓存策略

```ts
storefront.CacheNone()      // 不缓存（购物车、个性化内容）
storefront.CacheShort()     // 短期（库存、价格）
storefront.CacheLong()      // 长期（商品描述、静态内容）
storefront.CacheCustom({ maxAge: 60, staleWhileRevalidate: 600 })
```

**缓存策略是 Hydrogen 性能的核心**。用错了要么数据陈旧，要么打爆 API 限流。

## 12. 流式渲染（Hydrogen 的性能杀手锏）

```tsx
export async function loader({ context }: LoaderFunctionArgs) {
  // 关键数据：await，阻塞首屏
  const criticalData = await context.storefront.query(PRODUCT_QUERY);

  // 次要数据：不 await，返回 Promise
  const recommendations = context.storefront.query(RECOMMENDATIONS_QUERY);

  return { criticalData, recommendations };
}

export default function ProductPage() {
  const { criticalData, recommendations } = useLoaderData<typeof loader>();

  return (
    <>
      <ProductDetail product={criticalData.product} />

      <Suspense fallback={<Skeleton />}>
        <Await resolve={recommendations}>
          {(data) => <Recommendations products={data.products} />}
        </Await>
      </Suspense>
    </>
  );
}
```

**效果**：商品详情立刻显示，推荐商品慢慢流进来。首屏时间不被慢查询拖累。

**这是 [02 号文档](02-React知识补充清单.md) 里 C4（Suspense）唯一需要补的场景。**

## 13. 购物车与结账

```tsx
export async function action({ request, context }: ActionFunctionArgs) {
  const { cart } = context;
  const formData = await request.formData();

  const result = await cart.addLines([
    { merchandiseId: formData.get("variantId") as string, quantity: 1 },

很多人对 Hydrogen 的期待是"全流程自定义"，这一点要先说清楚。

## 16. 目录结构（核实自 Shopify/dawn 仓库）

## 17. 写你的第一个 Section

`sections/featured-products.liquid`：

```liquid
<div class="featured-products" style="padding: {{ section.settings.padding }}px 0;">
  <h2>{{ section.settings.heading }}</h2>

  <div class="product-grid">
    {%- for product in section.settings.collection.products limit: section.settings.count -%}
      <a href="{{ product.url }}" class="card">
        {%- if product.featured_image -%}
          <img
            src="{{ product.featured_image | image_url: width: 400 }}"
            alt="{{ product.featured_image.alt | escape }}"
            loading="lazy"
            width="400"
            height="{{ 400 | divided_by: product.featured_image.aspect_ratio | round }}"
          >
        {%- endif -%}
        <h3>{{ product.title }}</h3>
        <span>{{ product.price | money }}</span>
        {%- unless product.available -%}
          <span class="sold-out">{{ 'products.product.sold_out' | t }}</span>
        {%- endunless -%}
      </a>
    {%- else -%}
      <p>请在主题编辑器中选择一个商品系列</p>
    {%- endfor -%}
  </div>
</div>

{% schema %}
{
  "name": "精选商品",
  "tag": "section",
  "class": "section",
  "settings": [
    {
      "type": "text",
      "id": "heading",
      "label": "标题",
      "default": "精选商品"
    },
    {
      "type": "collection",
      "id": "collection",
      "label": "商品系列"
    },
    {
      "type": "range",
      "id": "count",
      "label": "显示数量",
      "min": 2, "max": 12, "step": 1, "default": 4
    },
    {
      "type": "range",
      "id": "padding",
      "label": "上下间距",
      "min": 0, "max": 100, "step": 4, "default": 40, "unit": "px"
    }
  ],
  "presets": [
    { "name": "精选商品" }
  ]
}
{% endschema %}
```

**四个要点**：
1. **`{% schema %}` 让商家能在编辑器里配置**——`settings` 定义了哪些可配，通过 `section.settings.xxx` 读取
2. **`presets` 让这个 section 出现在"添加区块"列表里**，没有它商家加不进去
3. **`{%- -%}` 的连字符去空白**，Dawn 到处都是
4. **`{% else %}` 在 for 循环里表示"列表为空时"**——这是 Liquid 特有的，处理空状态

### 常用过滤器速查

```liquid
{{ product.price | money }}                  {# 4999 → $49.99 #}
{{ image | image_url: width: 400 }}          {# CDN 图片 URL #}
{{ 'key' | t }}                              {# 多语言翻译 #}
{{ text | escape }}                          {# HTML 转义，防 XSS #}
{{ title | handleize }}                      {# "My Product" → "my-product" #}
{{ obj | json }}                             {# 转 JSON，用于传给 JS #}
{{ date | date: '%Y-%m-%d' }}
{{ list | where: 'available', true }}
{{ list | map: 'title' | join: ', ' }}
{{ value | default: '未设置' }}
```

## 18. Theme 里的交互：Web Components

Dawn 用原生自定义元素组织 JS，**没有框架**：

```html
<quantity-input class="quantity">
  <button name="minus" type="button">−</button>
  <input type="number" name="quantity" value="1" min="1">
  <button name="plus" type="button">+</button>
</quantity-input>

<script>
  class QuantityInput extends HTMLElement {
    constructor() {
      super();
      this.input = this.querySelector('input');
      this.querySelectorAll('button').forEach((btn) =>
        btn.addEventListener('click', this.onChange.bind(this))
      );
    }
    onChange(event) {
      const delta = event.target.name === 'plus' ? 1 : -1;
      this.input.value = Math.max(1, Number(this.input.value) + delta);
      this.input.dispatchEvent(new Event('change', { bubbles: true }));
    }
  }
  customElements.define('quantity-input', QuantityInput);
</script>
```

**这就是 [03 号文档第 6 节](03-其他前端知识清单.md) 讲的 Web Components 在 Theme 线的用法。** 学一次，App 线（Polaris WC）和 Theme 线（Dawn）都受益。

## 20. Theme 线常见卡点

| 症状 | 原因 | 解决 |
|---|---|---|
| section 不出现在"添加区块"里 | 缺 `presets` | schema 里加 `"presets": [{"name": "..."}]` |
| 改了 schema 编辑器没变化 | 缓存 | 重启 `shopify theme dev` |
| 图片模糊 | 没指定合适宽度 | `image_url: width: 800`，配合 srcset |
| 页面有多余空白 | Liquid 标签换行产生空白 | 用 `{%-` 和 `-%}` |
| 商家改了设置没生效 | 读错了作用域 | `section.settings` vs `block.settings` vs `settings`（全局） |
| JS 在编辑器里失效 | 编辑器动态加载 section 时不会重跑脚本 | 监听 `shopify:section:load` 事件 |
