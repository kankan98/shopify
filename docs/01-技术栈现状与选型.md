# 01 · 技术栈现状与选型

> 目标：10 分钟内搞清楚"Shopify 开发"这四个字底下到底藏着三个完全不同的工种。

---

## 1. 为什么必须先分清三条线

"我想学 Shopify 开发"这句话，在 2026 年等价于"我想学互联网开发"——太笼统了。Shopify 生态里有三个技术栈几乎不重叠的方向：

```
                    ┌─────────────────────────────────────┐
                    │         Shopify 平台                 │
                    │  （商品/订单/客户/结账 的数据与业务）  │
                    └─────────────────────────────────────┘
                       ▲              ▲              ▲
          Admin API    │   Storefront │   Liquid     │
          （管理数据）  │   API（读店面）│  （模板渲染）  │
                       │              │              │
              ┌────────┴───┐   ┌──────┴─────┐  ┌─────┴──────┐
              │  ① App     │   │ ② Hydrogen │  │ ③ Theme    │
              │  应用开发   │   │  无头商店   │  │  主题开发   │
              └────────────┘   └────────────┘  └────────────┘
              给商家装的插件      自建高性能店面    改店铺外观
              React Router 7    React Router 7   Liquid
              React ★★★★★      React ★★★★★     React ☆☆☆☆☆
```

三条线对应的**雇主/客户也不同**：
- App 线 → 你的用户是**商家**，你在 App Store 上架卖订阅。
- Hydrogen 线 → 你的用户是**一个具体品牌**，你给他做官网。
- Theme 线 → 你的用户是**商家或主题市场**，你改/卖主题。

---

## 2. 三条线逐个拆解

### ① App 应用开发（Shopify App）

**是什么**：商家在 Shopify 后台点"安装应用"装上的插件。安装后在商家后台左侧出现一个菜单项，点进去是**嵌在 iframe 里的你的网站**。

**典型场景**：库存同步、批量改价、忠诚度积分、退货管理、和第三方 ERP 对接。

**技术栈（2026-07 核实自官方模板）**：

```json
{
  "dependencies": {
    "@react-router/dev": "^7.12.0",
    "@react-router/fs-routes": "^7.12.0",
    "@react-router/node": "^7.12.0",
    "@react-router/serve": "^7.12.0",
    "@shopify/app-bridge-react": "^4.2.4",
    "@shopify/shopify-app-react-router": "^1.1.0",
    "@shopify/shopify-app-session-storage-prisma": "^9.0.0",
    "@prisma/client": "^6.16.3",
    "react": "^18.3.1",
    "react-dom": "^18.3.1",
    "react-router": "^7.12.0"
  },
  "devDependencies": {
    "@shopify/api-codegen-preset": "^2.0.0",
    "@shopify/polaris-types": "1.0.1",
    "typescript": "^5.9.3",
    "vite": "^7.3.1"
  }
}
```

注意几个**信息量极大**的点：

1. **没有 `@shopify/polaris`**，只有 `@shopify/polaris-types`。因为 UI 组件不再通过 npm 包引入，而是 App Bridge 在运行时注入的自定义元素，npm 里只需要类型定义供 TS 检查。
2. **有 Prisma**。App 需要自己的数据库存 session（商家的 access token），模板默认 SQLite + Prisma。所以你会被迫接触一点后端和 ORM。
3. **有 `@shopify/api-codegen-preset`**。GraphQL 查询会被扫描并自动生成 TS 类型。

**服务端入口长这样**（`app/shopify.server.ts`，真实模板代码）：

```ts
import "@shopify/shopify-app-react-router/adapters/node";
import { ApiVersion, AppDistribution, shopifyApp } from "@shopify/shopify-app-react-router/server";
import { PrismaSessionStorage } from "@shopify/shopify-app-session-storage-prisma";
import prisma from "./db.server";

const shopify = shopifyApp({
  apiKey: process.env.SHOPIFY_API_KEY,
  apiSecretKey: process.env.SHOPIFY_API_SECRET || "",
  apiVersion: ApiVersion.October25,
  scopes: process.env.SCOPES?.split(","),
  appUrl: process.env.SHOPIFY_APP_URL || "",
  authPathPrefix: "/auth",
  sessionStorage: new PrismaSessionStorage(prisma),
  distribution: AppDistribution.AppStore,
  future: { expiringOfflineAccessTokens: true },
});

export default shopify;
export const authenticate = shopify.authenticate;
```

**你需要理解的核心概念**：OAuth 安装流程、session token（嵌入式应用用 JWT 而非 cookie）、scopes 权限、webhook、App Bridge、iframe 嵌入限制。

**难度**：★★★★☆ ——三条线里最高，因为你要同时是前端 + 后端 + 平台集成工程师。

**收益**：★★★★★ ——可以做成 SaaS 订阅收入。

---

### ② Hydrogen 无头商店（Headless Storefront）

**是什么**：不用 Shopify 的主题系统，自己写一个网站当店面，通过 **Storefront API** 拉商品数据、管理购物车，结账时跳回 Shopify 的 Checkout。Hydrogen 是 Shopify 官方的 React 框架，Oxygen 是配套的全球边缘部署平台（对 Hydrogen 免费）。

**典型场景**：品牌方要极致性能、极度定制的设计、或要把商城嵌进现有的内容站。

**技术栈（2026-07 核实自 `templates/skeleton/package.json`）**：

```json
{
  "version": "2026.4.5",
  "dependencies": {
    "@shopify/hydrogen": "workspace:*",
    "graphql": "^16.10.0",
    "graphql-tag": "^2.12.6",
    "react": "^18.3.1",
    "react-dom": "^18.3.1",
    "react-router": "7.16.0",
    "react-router-dom": "7.16.0"
  },
  "devDependencies": {
    "@shopify/cli": "3.93.2",
    "@shopify/mini-oxygen": "workspace:*",
    "@shopify/oxygen-workers-types": "^4.1.6",
    "@react-router/dev": "7.16.0",
    "@graphql-codegen/cli": "5.0.2",
    "vite": "^8.0.1",
    "typescript": "^5.9.2"
  },
  "engines": { "node": "^22 || ^24" }
}
```

命令：

```json
{
  "dev": "shopify hydrogen dev --codegen",
  "build": "shopify hydrogen build --codegen",
  "preview": "shopify hydrogen preview --build",
  "typecheck": "react-router typegen && tsc --noEmit"
}
```

**注意 `@shopify/oxygen-workers-types`**：Oxygen 运行在 **Workers 运行时**（类 Cloudflare Workers），不是完整 Node。意味着 `fs`、`path`、大部分 Node 内置模块用不了，很多 npm 包装上会炸。这是 Hydrogen 线最大的隐性门槛。

**你需要理解的核心概念**：SSR（服务端渲染）、流式渲染、缓存策略（`CacheShort/CacheLong`）、Storefront API vs Admin API 的区别、cart 的状态管理、SEO。

**难度**：★★★★☆ ——React 深度最高（SSR + 缓存 + 边缘运行时）。

**收益**：★★★☆☆ ——通常是项目制收入，不易规模化。

---

### ③ Theme 主题开发（Online Store 2.0）

**是什么**：Shopify 自带的店面系统。你写 **Liquid** 模板（一种服务端模板语言，像 Jinja/Twig），商家在后台可视化编辑器里拖拽 section。

**目录结构（核实自 Shopify 官方 Dawn 主题仓库）**：

```
dawn/
├── assets/        # CSS、JS、图片
├── config/        # settings_schema.json（主题设置项）、settings_data.json
├── layout/        # theme.liquid（HTML 骨架）
├── locales/       # 多语言 JSON
├── sections/      # 可拖拽的区块（OS 2.0 核心）
├── snippets/      # 可复用片段
└── templates/     # 页面模板（JSON 格式，OS 2.0）
```

**Liquid 长这样**：

```liquid
{%- for product in collection.products -%}
  <div class="card">
    <a href="{{ product.url }}">
      <img src="{{ product.featured_image | image_url: width: 400 }}" alt="{{ product.title | escape }}">
      <h3>{{ product.title }}</h3>
      <span>{{ product.price | money }}</span>
    </a>
  </div>
{%- endfor -%}
```

**技术栈**：Liquid + 原生 HTML/CSS/JS。**没有 React，没有构建工具，没有 npm**（Dawn 连 package.json 都没有）。前端交互用原生 Web Components 写——Dawn 大量使用 `customElements.define`。

**你需要理解的核心概念**：Liquid 对象与过滤器、section schema、blocks、metafields、Ajax Cart API、theme editor 的工作方式。

**难度**：★★☆☆☆ ——三条线里最低。

**收益**：★★★☆☆ ——外包单价不高但需求量大，入门快。

## 3. 三条线的知识重叠度

这张表决定了你的学习顺序性价比：

| 知识块 | App | Hydrogen | Theme | 复用度 |
|---|:---:|:---:|:---:|:---:|
| Shopify 领域模型（product/variant/cart…） | ✅ | ✅ | ✅ | ★★★ |
| GraphQL 基础 + Relay 分页 | ✅ | ✅ | ⚠️ | ★★★ |
| React | ✅ | ✅ | ❌ | ★★ |
| React Router 7（loader/action） | ✅ | ✅ | ❌ | ★★ |
| TypeScript | ✅ | ✅ | ❌ | ★★ |
| Vite / 现代构建 | ✅ | ✅ | ❌ | ★★ |
| Web Components | ✅（Polaris） | ⚠️ | ✅（Dawn） | ★★ |
| Node.js / 包管理 | ✅ | ✅ | ❌ | ★★ |
| Admin API | ✅ | ⚠️ | ❌ | ★ |
| Storefront API | ⚠️ | ✅ | ⚠️ | ★ |
| OAuth / session token / webhook | ✅ | ❌ | ❌ | ★ |
| SSR / 边缘运行时 / 缓存 | ⚠️ | ✅ | ❌ | ★ |
| Liquid | ❌ | ❌ | ✅ | ★ |
| Prisma / 数据库 | ✅ | ❌ | ❌ | ★ |
| CSS 深度 | ⚠️ | ✅ | ✅ | ★★ |

图例：✅ 必需　⚠️ 部分场景需要　❌ 用不上

**读表结论**：
- **Shopify 领域模型 + GraphQL** 是唯一三线全需的，优先级最高，且和 React 无关——可以在学 React 之前就搞定。这就是 README 里建议"先 Theme 两周"的依据。
- **React + React Router 7 + TypeScript** 是 App 和 Hydrogen 的共同底座，一次投入两线通吃。
- Theme 线是知识孤岛（Liquid 不迁移），但它的**领域模型收益**可迁移。

## 4. 选型决策树

```
Q1: 你的目标是产品化收入，还是接单/自用？
    ├─ 产品化收入 ────────────────────────► App 线
    └─ 接单 / 自用
         │
    Q2: 客户对性能和设计自由度有极端要求吗？
         ├─ 有（要 100 分 Lighthouse、要奇特交互）──► Hydrogen 线
         └─ 没有（就是个正常的品牌店）
              │
         Q3: 你想尽快接到第一单吗？
              ├─ 是 ──────────────────────► Theme 线
              └─ 否，愿意投 3-6 个月 ───────► App 线
```

**反直觉提醒**：不要因为"Hydrogen 看起来最酷/最新"就选它。Hydrogen 的商业需求量远小于 Theme 和 App，且大部分中小商家用主题就够了。**技术先进性 ≠ 就业/接单机会。**

## 5. 术语对照表（先混个眼熟）

学 Shopify 前 20 小时最大的痛苦不是技术，是术语。先扫一眼：

| 术语 | 含义 | 常见误解 |
|---|---|---|
| **Product / Variant** | 商品 / 商品的具体规格（红色-L码） | 以为 Product 就是可售单元。**实际能被加入购物车的是 Variant，不是 Product** |
| **Collection** | 商品分类集合 | 有 manual（手动）和 smart（规则自动）两种 |
| **Metafield** | 自定义字段，挂在任何资源上 | Shopify 的"扩展一切"的方式，极其重要 |
| **Metaobject** | 自定义数据结构（类似自定义表） | 比 metafield 更新，用于结构化内容 |
| **Checkout** | 结账流程 | **不可自定义**（Plus 套餐外）。Hydrogen 也必须跳转到 Shopify Checkout |
| **Admin API** | 管理数据的 API（读写订单、商品、客户） | 需要 access token，只能服务端调 |
| **Storefront API** | 面向买家的公开 API（读商品、操作购物车） | 可以在浏览器调，有公开 token |
| **App Bridge** | 让 iframe 里的 App 和 Shopify 后台通信的库 | 现在还负责注入 Polaris Web Components |
| **Session Token** | 嵌入式 App 的身份凭证（JWT，1 分钟过期） | 不是 cookie。iframe 里 cookie 会被浏览器拦 |
| **Access Token** | 代表商家授权的长期 token | 存数据库里，绝不能泄露到前端 |
| **Scopes** | 权限范围（`read_products,write_orders`） | 改了要重新走授权 |
| **Webhook** | Shopify 主动推事件给你（订单创建等） | 必须验 HMAC 签名，否则可被伪造 |
| **Section / Block** | 主题里可拖拽的区块 / 区块内的子项 | OS 2.0 的核心概念 |
| **Liquid** | Shopify 的服务端模板语言 | 只在 Theme 线用 |
| **Dev Store** | 开发用的免费测试店铺 | 可以下测试订单，不能真收款 |
| **Partner 账号** | 开发者账号 | 免费，App 和 Dev Store 都在这建 |

**Relay Connection 格式**（GraphQL 里最劝退的一点，先看一眼）：

Shopify 所有列表查询都是这个套娃结构，不是简单数组：

```graphql
{
  products(first: 10) {
    edges {
      node { id title }        # ← 真正的数据在 edges[].node 里
      cursor                   # ← 用于翻页
    }
    pageInfo { hasNextPage endCursor }
  }
}
```

在 JS 里取数据要写 `data.products.edges.map(e => e.node)`。真实模板代码里就是这么写的：

```ts
const variantId = product.variants.edges[0]!.node!.id!;
```

这块详见 [06 号文档](06-TypeScript与GraphQL教程.md)。
