# 第一部分 · 认知性大坑（最贵的那种）

这类坑的代价不是浪费几小时，是**浪费几周学错东西**。

## ⚠️ 坑 1：跟着教程学 Polaris React

**症状**：你在网上找到一篇"Shopify App 开发入门"，照着 `import { Page, Card, Button } from '@shopify/polaris'` 写。

**真相**：官方仓库 README 第一行——

> **# Polaris React (⚠️ Deprecated)**
> The Shopify Polaris React library is deprecated. We are no longer accepting contributions or feature requests in this repository.
> On October 1, 2025, we released our Polaris Web Components for Shopify app development.

**正确做法**：用 Polaris Web Components（`<s-page>` `<s-button>`）。判断一篇教程是否过时，只看这一条。

**如何验证**：`npm create @shopify/app@latest` 拉最新模板，看 package.json 里有没有 `@shopify/polaris`。现在只有 `@shopify/polaris-types`。

---

## ⚠️ 坑 2：用 useEffect + fetch 拉 Shopify 数据

**症状**：

```jsx
useEffect(() => {
  fetch('/api/products').then(r => r.json()).then(setProducts);
}, []);
```

**为什么是坑**：
1. Admin API 需要 API secret，**在浏览器里根本调不了**
2. 即使包一层自己的 API，也多了一次往返，首屏变慢
3. 有竞态条件问题
4. 和框架的数据流打架

**正确做法**：用 `loader`。见 [07 号文档](07-ReactRouter7数据流教程.md)。

---

## ⚠️ 坑 3：把该放 URL 的状态放进 useState

**症状**：分页页码、搜索词、筛选条件用 `useState` 管。

**后果**：用户翻到第 5 页刷新 → 回到第 1 页。把链接发给同事 → 同事看到的不是同一个结果。

**判断法则**：问"用户刷新页面 / 分享这个链接，这个状态应该保留吗？"应该 → 放 URL。

---

## ⚠️ 坑 4：装一堆用不上的库

**症状**：Redux、Zustand、React Query、Axios、Ant Design……

**真相**：在 RR7 全栈架构下：
- 服务器数据 → loader（不需要 React Query）
- URL 状态 → searchParams（不需要 Redux）
- 请求 → 服务端的 `admin.graphql()`（不需要 Axios）
- UI → Polaris Web Components（不需要组件库，而且**审核会看你是否遵循 Shopify 设计规范**）

**每装一个库，你都在给自己增加一份不必要的学习成本和维护负担。**

---

## ⚠️ 坑 5：选错了线路才发现

**症状**：想做 Hydrogen，因为"看起来最新最酷"。做了两个月发现没有客户需求。

**真相**：技术先进性 ≠ 商业机会。Hydrogen 的需求量远小于 Theme 和 App。

**建议**：先看 [01 号文档的选型决策树](01-技术栈现状与选型.md)。

# 第二部分 · 环境与工具类

| 症状 | 原因 | 解决 |
|---|---|---|
| `npm install` 一堆 engine 警告 | Node 版本不对 | App 要 `>=20.19 <22 \|\| >=22.12`，Hydrogen 要 `^22 \|\| ^24`。装 22.12+ 通吃 |
| `require is not defined` | 模板是 ESM（`"type": "module"`） | 用 `import`；`__dirname` 用 `fileURLToPath(import.meta.url)` |
| `shopify` 命令找不到 | CLI 没装或不在 PATH | `npm install -g @shopify/cli` |
| dev 隧道地址每次都变 | 正常行为 | `shopify app dev` 会自动更新 App 配置，别手动改 |
| 改了 `.env` 没生效 | 需要重启 dev server | Ctrl+C 重启 |
| `.env` 被提交到 git | `.gitignore` 没配好 | 立刻 revoke 泄露的 secret，然后修 gitignore |
| 团队成员装出不同的依赖 | 没提交 lockfile | `package-lock.json` / `pnpm-lock.yaml` 必须提交 |

# 第三部分 · React / TypeScript 类

| 症状 | 原因 | 解决 |
|---|---|---|
| 改了 state 界面不更新 | 直接改了原对象/数组 | 用不可变更新：`setList([...list, x])` |
| 连续 `setCount(count+1)` 只加了 1 | 每次渲染的 count 是快照 | 用函数式：`setCount(c => c+1)` |
| 列表增删后输入框内容错位 | 用了 index 当 key | 用稳定唯一 id |
| 页面上莫名出现一个 "0" | `{items.length && <X/>}` 且 length 为 0 | 写成 `{items.length > 0 && <X/>}` |
| useEffect 执行了两次 | React 18 StrictMode 开发环境故意的 | 不是 bug。检查你的清理函数写对没有 |
| 无限重渲染 | effect 依赖里有每次都变的引用 | 检查依赖数组；对象/函数依赖考虑 useMemo/useCallback |
| `Hooks can only be called inside...` | 在条件/循环/嵌套函数里调了 Hook | Hook 只能在组件顶层调用 |
| TS 报 `Property 'x' does not exist` | GraphQL 返回类型是可选的 | 用可选链 + 空检查，或跑 codegen 生成精确类型 |
| 一堆 `Object is possibly null` | strict 模式 | 写 null 检查（比 `!` 好），或用可选链 |
| `tsc --noEmit` 慢 | 正常 | 用 `--incremental` |

# 第四部分 · Polaris Web Components 类

| 症状 | 原因 | 解决 |
|---|---|---|
| `<s-page>` TS 报"不认识这个标签" | 缺类型声明 | 确认 `@shopify/polaris-types` 在 devDependencies 里，别删 |
| 按钮一直显示 loading | `loading={false}` 渲染成 `loading="false"`，HTML 里 attribute 存在即为真 | 用条件展开：`{...(isLoading ? {loading: true} : {})}` |
| 传数组/对象属性不生效 | React 18 把它转成了字符串塞进 attribute | 用 `ref` 直接赋 property |
| 自定义事件监听不到 | React 合成事件不覆盖非标准事件名 | 用 `ref` + `addEventListener` |
| CSS 改不动组件内部样式 | Shadow DOM 隔离 | 用组件暴露的 CSS 自定义属性或 `::part()`，不要硬改 |
| 文档里的元素名和代码里对不上 | 命名正在从 `ui-` 迁移到 `s-` | 以模板实际 markup 和官方文档为准，不以包内类型声明为准 |

**关于最后一条的实证**：`@shopify/app-bridge-react@4.2.4` 的类型里声明的是 `ui-modal` / `ui-nav-menu` / `ui-save-bar` / `ui-title-bar`，但官方模板 `app.tsx` 的 markup 用的是 `<s-app-nav>`，而 `app.additional.tsx` 的说明文字里还写着"`<ui-nav-menu>` component found in `app/routes/app.jsx`"（连文件后缀都是过时的 `.jsx`）。**官方自己的模板都存在新旧混用，你遇到不一致时别怀疑自己。**

# 第五部分 · GraphQL / API 类

| 症状 | 原因 | 解决 |
|---|---|---|
| Mutation 返回 200 但数据是 null | 业务失败，错误在 `userErrors` 里 | **查询并检查 `userErrors`**——这是最高频的线上事故 |
| 报 `THROTTLED` / HTTP 429 | 超过查询成本限额 | 减小 `first`；加指数退避重试；大批量用 Bulk Operations |
| `data.products.map is not a function` | Relay 结构，数据在 `edges[].node` 里 | `data.products.edges.map(e => e.node)` 或用 `nodes` 简写 |
| 传 ID 报错 | 用了数字 ID | 用完整 GID：`gid://shopify/Product/123` |
| 字段查不到 / 报权限错 | scopes 不够 | 改 `shopify.app.toml` 的 scopes 并重装 App |
| 某个字段在文档里有代码里没有 | API 版本不对 | 检查 `apiVersion`，模板锁的是 `October25` |
| 分页翻着翻着数据重复/丢失 | 用了 offset 思维 | 必须用 cursor：`after: pageInfo.endCursor` |
| 想跳到第 5 页做不到 | 游标分页的固有限制 | 设计上避免跳页；或用搜索/筛选缩小结果集 |

## GraphQL 错误处理模板（直接抄）

```ts
async function runMutation(admin, mutation, variables, resultKey: string) {
  // 第 1 层：传输层
  const res = await admin.graphql(mutation, { variables });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);

  const json = await res.json();

  // 第 2 层：GraphQL 层
  if (json.errors?.length) throw new Error(json.errors[0].message);

  // 第 3 层：业务层
  const payload = json.data?.[resultKey];
  if (payload?.userErrors?.length) {
    const e = payload.userErrors[0];
    throw new Error(`${e.field?.join('.') ?? ''}: ${e.message}`);
  }

  return payload;
}
```

# 第六部分 · App 运行时类

| 症状 | 原因 | 解决 |
|---|---|---|
| 商家后台里 App 白屏 | CSP `frame-ancestors` header 不对 | 检查每个路由有没有导出 `headers = boundary.headers` |
| `authenticate.admin` 抛 401 | session token 过期 / scopes 变了 | 重装 App |
| 生产环境 session 随机丢失 | SQLite 在多实例部署下不共享 | 换 Postgres/MySQL |
| Webhook 收到了但处理了多次 | Shopify 是"至少一次"投递 | 处理逻辑必须**幂等** |
| Webhook 一直重试 | 你返回慢了或返回了非 2xx | 快速返回 200，重活扔队列 |
| Webhook 被伪造攻击 | 没验 HMAC | 用 `authenticate.webhook(request)`，别自己解析 body 绕过 |
| 在 iframe 里 cookie 存不住 | 第三方 cookie 被浏览器拦截 | 这就是用 session token 的原因，别试图用 cookie |
| DevTools 里看不到 App 的 DOM | 你在看外层页面 | DevTools 右上角切换 frame 到 App 的那个 |
| `console.log` 在浏览器里看不到 | 它在 loader/action 里，跑在服务端 | 看启动 dev server 的**终端** |
| 提审被拒 | 缺 GDPR webhook / 性能不达标 / 违反设计规范 | 见下方上架清单 |

# 第七部分 · Hydrogen 类

| 症状 | 原因 | 解决 |
|---|---|---|
| 装了个 npm 包就构建失败 | Oxygen 是 Workers 运行时，不是 Node | 选标注 "edge/workers compatible" 的包 |
| `fs is not defined` / `process is not defined` | 同上 | 找 Web 标准 API 替代 |
| Hydration mismatch 报错 | 服务端和客户端渲染结果不一致 | 检查有没有用 `Date.now()`、`Math.random()`、`window` 等 |
| 数据陈旧 | 缓存策略太长 | 库存/价格用 `CacheShort()`，购物车用 `CacheNone()` |
| 打爆 Storefront API 限流 | 缓存策略太短或没缓存 | 静态内容用 `CacheLong()` |
| 首屏慢 | 所有查询都 await 了 | 次要数据不 await，配合 `Suspense` + `<Await>` |
| 想自定义结账页 | 做不到 | Checkout 不可自定义（Plus 套餐外），必须跳转 |

# 第八部分 · Theme 类

| 症状 | 原因 | 解决 |
|---|---|---|
| section 不出现在"添加区块"列表 | schema 缺 `presets` | 加 `"presets": [{"name": "..."}]` |
| 改了 schema 编辑器没反应 | 缓存 | 重启 `shopify theme dev` |
| 页面出现莫名空白 | Liquid 标签换行产生的空白节点 | 用 `{%-` 和 `-%}` |
| 设置项读不到值 | 作用域搞混了 | `settings`（全局）/ `section.settings` / `block.settings` 是三个不同的东西 |
| 编辑器里加了 section 但 JS 不工作 | 编辑器动态注入时不会重跑 script | 监听 `shopify:section:load` 事件 |
| 图片模糊或加载慢 | 没指定合适宽度 | `image_url: width: 800`，配 srcset 和 `loading="lazy"` |
| 用户输入直接输出导致 XSS | 没转义 | 所有用户内容加 `| escape` |

# 第十一部分 · 如何判断一篇教程是否过时

按顺序检查，命中任何一条就别看了：

```
□ 用 import { Page, Card } from '@shopify/polaris'
      → 已废弃（2025-10-01），立刻放弃

□ 用 @remix-run/* 包名
      → 遗留分支，现役是 react-router

□ 用 REST Admin API（/admin/api/2023-01/products.json）
      → GraphQL 才是现在的路

□ 用 class 组件、componentDidMount
      → React 内容过时（2019 年前）

□ 用 useEffect + fetch 拉 Shopify 数据
      → 架构错误

□ 教你装 Redux 管理 Shopify App 状态
      → 不需要，作者没理解全栈框架

□ 发布日期早于 2025-10
      → Polaris 换代的分水岭，之前的 App 教程 UI 部分全部作废
```

**最可靠的做法**：任何时候拿不准，就 `npm create @shopify/app@latest` 拉一次最新模板，看它实际怎么写。

# 第十二部分 · 卡住时的排查顺序

```
1. 报错信息完整读一遍（不要只看第一行）
       ↓
2. 是编译期错误还是运行时错误？
   编译期 → 大概率是 TS 类型或 import 问题
   运行时 → 继续
       ↓
3. 错误发生在服务端还是客户端？
   看终端有没有输出 → 服务端（loader/action）
   看浏览器 Console → 客户端（组件）
       ↓
4. 是 Shopify 相关还是通用前端问题？
   通用 → MDN / React 文档 / Stack Overflow
   Shopify → 继续
       ↓
5. 打开 Network 面板，看实际发出的 GraphQL 请求和响应
   （90% 的 Shopify 问题在这一步就能定位）
       ↓
6. 把同样的查询扔进 GraphiQL 跑一遍
   GraphiQL 里能跑通 → 你的代码问题
   GraphiQL 里也失败 → 查询本身或权限问题
       ↓
7. 对照官方模板：同样的事情它是怎么写的？
       ↓
8. 还不行 → Shopify 社区论坛 / GitHub Issues
```
