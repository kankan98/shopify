### 三个必须特别注意的点

**① ESM vs CommonJS**
Shopify 模板全是 `"type": "module"`（ESM）。你可能习惯的 `require()` / `module.exports` 在里面会直接报错。

```js
// ❌ ESM 里不能用
const x = require('x');
__dirname

// ✅
import x from 'x';
import { fileURLToPath } from 'url';
const __dirname = path.dirname(fileURLToPath(import.meta.url));
```

**② `??` vs `||`**

```js
const port = 0 || 3000;    // → 3000  （0 是假值，被跳过，可能不是你想要的）
const port = 0 ?? 3000;    // → 0     （只有 null/undefined 才走右边）
```

模板里大量出现 `process.env.X || ""`，理解它的语义。

**③ 非空断言在 JS 里不存在，但你会在模板里看到 `!`**

```ts
const variantId = product.variants.edges[0]!.node!.id!;
```

这是 **TypeScript 语法**（非空断言），编译后会消失。见第 3 节。

# 2. Node.js 与包管理 🔴

> 你要跑一个服务端应用了，不再是"写个 HTML 双击打开"。

### 必须掌握

**Node 版本管理**
```bash
brew install fnm            # 或 nvm
fnm install 22 && fnm use 22
```
为什么重要：App 模板要求 `>=20.19 <22 || >=22.12`，Hydrogen 要求 `^22 || ^24`。装错版本第一步就跑不起来。

**package.json 关键字段**
```jsonc
{
  "type": "module",              // ESM 模式
  "scripts": { "dev": "shopify app dev" },   // npm run dev
  "dependencies": {},            // 运行时需要
  "devDependencies": {},         // 只开发时需要
  "engines": { "node": ">=22.12" }
}
```

**语义化版本（SemVer）**
```
^1.2.3  → 允许 1.x.x（不改主版本）    ← 最常见
~1.2.3  → 允许 1.2.x
1.2.3   → 精确锁定（Hydrogen 对 react-router 就用了精确锁）
```

**lockfile**：`package-lock.json` / `pnpm-lock.yaml` **必须提交到 git**，它保证团队/CI 装到完全一样的依赖树。

**npm vs pnpm**：Hydrogen 官方仓库用 pnpm（`pnpm@10.16.1`），App 模板 npm 即可。pnpm 更省磁盘、更严格（不允许用没声明的依赖）。

**环境变量**
```bash
# .env（绝对不能提交到 git）
SHOPIFY_API_KEY=xxx
SHOPIFY_API_SECRET=xxx
```
```js
process.env.SHOPIFY_API_KEY
```
理解"服务端环境变量 vs 客户端可见变量"的区别——**secret 泄露到前端 = 灾难**。

### 常用命令
```bash
npm install              # 按 lockfile 装
npm ci                   # CI 环境用，严格按 lockfile
npm run dev
npx <包名>               # 临时执行不安装
npm outdated             # 看哪些包过期了
```

# 3. TypeScript 🔴🔴

> **App 和 Hydrogen 两条线的官方模板都是 100% TypeScript。**你没有"先用 JS 写，以后再说"的选项——模板文件后缀就是 `.tsx`。
> 好消息：**你不需要成为 TS 专家**。做 Shopify 开发用到的 TS 大概是全部 TS 的 25%。

### 必须掌握（约 15h）

```ts
// 基础类型标注
let n: number = 1;
let s: string = 'a';
let b: boolean = true;
let arr: string[] = [];
let tuple: [string, number] = ['a', 1];
let anything: unknown;              // 比 any 安全，用之前必须收窄

// 对象类型
interface Product { id: string; title: string; price?: number }   // ? = 可选
type Status = 'draft' | 'active' | 'archived';                    // 联合类型（超常用）

// 函数
function f(a: string, b = 0): Promise<Product> {}
const g = (x: number): void => {};

// 泛型（必须懂，因为 useLoaderData<typeof loader>() 就是泛型）
function first<T>(arr: T[]): T | undefined { return arr[0]; }

// 类型收窄
if (typeof x === 'string') { /* 这里 x 是 string */ }
if (x) { /* 排除了 null/undefined */ }
if ('id' in obj) {}

// 常用工具类型
Partial<T>  Required<T>  Pick<T,'a'|'b'>  Omit<T,'a'>  Record<string, T>
ReturnType<typeof fn>   Awaited<T>

// 类型查询（Shopify 模板高频）
typeof loader                       // 拿函数的类型
Awaited<ReturnType<typeof loader>>  // 拿它 resolve 后的类型

// 断言（谨慎用）
const el = ref.current as HTMLInputElement;
const id = product.id!;             // 非空断言：告诉 TS"我保证不是 null"

// as const
const SIZES = ['s','m','l'] as const;   // 类型变成 readonly ['s','m','l']
```

### Shopify 模板里实际出现的 TS 用法

```tsx
// ① 框架提供的类型
import type { ActionFunctionArgs, LoaderFunctionArgs, HeadersFunction } from "react-router";

export const loader = async ({ request }: LoaderFunctionArgs) => { ... };

// ② 泛型串起服务端和客户端的类型（TS 的精髓所在）
const data = useLoaderData<typeof loader>();
//    ^ data 的类型自动等于 loader 的返回类型，改了 loader 这里立刻报错

const fetcher = useFetcher<typeof action>();
//    ^ fetcher.data 自动有类型

// ③ 非空断言链（因为 GraphQL 返回类型全是可选的）
const product = responseJson.data!.productCreate!.product!;
const variantId = product.variants.edges[0]!.node!.id!;

// ④ import type（只导入类型，编译后消失）
import type { HeadersFunction } from "react-router";
```

### 需要理解但不用深挖
- `tsconfig.json` 的常见选项（`strict`、`paths`、`jsx`）——模板配好了，别乱改
- 声明文件 `.d.ts`（`@shopify/polaris-types` 就是纯声明包）
- `react-router typegen` 生成的类型（模板 `typecheck` 脚本里跑的）

### 可以完全跳过
装饰器、命名空间、抽象类、条件类型 `T extends U ? A : B`、映射类型、模板字面量类型。**做业务开发几乎用不到。**

### 学习资源
- [TypeScript 中文手册](https://ts.nodejs.cn/docs/handbook/intro.html) —— 只看 "Everyday Types"、"Narrowing"、"Generics" 三章
- [TypeScript 入门教程（阮一峰）](https://wangdoc.com/typescript/)
- 实践建议：**别单独学 TS**。装个 VS Code，把 React 教程的例子用 `.tsx` 写，报错了再去查。TS 是"用出来的"不是"读出来的"。

# 4. GraphQL + Relay 分页 🔴🔴

> **Shopify 的所有 API 都是 GraphQL**（REST Admin API 已在退场）。这块不会，你连商品列表都拉不出来。

### 4.1 GraphQL 基础

```graphql
# 查询：你要什么字段就写什么字段
query GetProduct($id: ID!) {          # $id 是变量，ID! 表示非空
  product(id: $id) {
    id
    title
    status
    priceRangeV2 { minVariantPrice { amount currencyCode } }
  }
}
```

```graphql
# 变更：写操作
mutation CreateProduct($product: ProductCreateInput!) {
  productCreate(product: $product) {
    product { id title handle }
    userErrors { field message }     # ⚠️ 必写！见下方 4.4
  }
}
```

在 Shopify App 里调用（真实模板代码）：

```ts
const response = await admin.graphql(
  `#graphql
    mutation populateProduct($product: ProductCreateInput!) {
      productCreate(product: $product) {
        product { id title handle status }
      }
    }`,
  { variables: { product: { title: "Red Snowboard" } } }
);
const responseJson = await response.json();
```

**注意那个 `#graphql` 注释**——它让编辑器和 codegen 工具识别这是 GraphQL 字符串，从而提供高亮、补全和类型生成。**别删。**

### 4.2 Relay Connection 分页（最劝退的一块）

Shopify 所有列表都是这个结构：

```graphql
query {
  products(first: 10, after: "eyJsYXN0X2lkIjo...") {
    edges {
      node { id title }
      cursor
    }
    pageInfo {
      hasNextPage
      hasPreviousPage
      startCursor
      endCursor
    }
  }
}
```

**为什么这么绕**：游标分页（cursor-based）而不是页码分页（offset-based）。好处是数据插入删除时不会跳页/漏数据，坏处是**不能跳到第 5 页**，只能一页页翻。

**JS 里的处理**：
```ts
const products = data.products.edges.map(e => e.node);
const nextCursor = data.products.pageInfo.endCursor;
const hasMore = data.products.pageInfo.hasNextPage;
```

**新版简写**：较新的 Shopify schema 也支持 `nodes` 直接拿数组：
```graphql
products(first: 10) { nodes { id title } }
```
但 `edges/node` 依然大量存在（尤其嵌套查询里），两种都要认。真实模板里就是 `product.variants.edges[0].node`。

### 4.3 全局 ID（GID）

Shopify 的 ID 不是数字，是这种字符串：
```
gid://shopify/Product/108828309
gid://shopify/ProductVariant/30322695
```
- 传给 API 时用完整 GID
- 从 REST 迁移过来的数字 ID 需要拼接
- 这个格式天然全局唯一，**适合直接当 React 的 key**

### 4.4 userErrors —— 最容易漏的一个坑 ⚠️

GraphQL 的 mutation **业务失败时 HTTP 状态码依然是 200**，错误藏在 `userErrors` 里：

```graphql
mutation {
  productCreate(product: {...}) {
    product { id }
    userErrors { field message }   # ← 必须查询它
  }
}
```
```ts
const json = await response.json();
if (json.data.productCreate.userErrors.length > 0) {
  // 业务失败：比如标题为空、SKU 重复
  throw new Error(json.data.productCreate.userErrors[0].message);
}
```

**不查 userErrors = 你的 App 会静默失败**。这是新手最高频的线上事故来源。

还要区分三层错误：
| 层 | 表现 | 例子 |
|---|---|---|
| 传输层 | HTTP 4xx/5xx | 网络断了、token 失效 |
| GraphQL 层 | `json.errors` | 查询语法错、字段不存在 |
| 业务层 | `json.data.X.userErrors` | 标题为空、库存不足 |

### 4.5 限流（Rate Limit）

Shopify GraphQL 用**计算成本**限流，不是请求数。返回体里有：
```json
{ "extensions": { "cost": { "requestedQueryCost": 52, "throttleStatus": { "currentlyAvailable": 948, "restoreRate": 50 } } } }
```
**含义**：漏桶算法，桶容量 1000 点，每秒恢复 50 点。查询字段越多、`first` 越大，成本越高。
**应对**：批量操作用 `bulkOperationRunQuery`；写重试 + 指数退避；别用 `first: 250` 一把梭。

### 4.6 代码生成（codegen）

模板自带 `@shopify/api-codegen-preset`（App）和 `@graphql-codegen/cli`（Hydrogen）。运行后会扫描你代码里的 `#graphql` 字符串，生成精确的 TS 类型。

```bash
npm run graphql-codegen      # App 线
npm run codegen              # Hydrogen 线
```

配好之后，`response.json()` 的结果就有完整类型提示了，**这是 TS 在这个栈里最大的价值**。

### 4.7 必用工具

**GraphiQL 探索器**——Shopify 内置的在线查询工具，能自动补全、看 schema、直接跑查询。
```bash
shopify app dev
# 启动后终端会给出一个 GraphiQL 地址
```
**建议：写任何 GraphQL 代码前，先在 GraphiQL 里调通再复制到项目。** 能节省 80% 的调试时间。

# 6. Web Components 🟠

> **因为 Polaris React 废弃了，这块从"可选"变成了 App 线的必修。** Theme 线的 Dawn 主题也大量用它。

### 需要掌握

```js
// 定义自定义元素
class MyCounter extends HTMLElement {
  connectedCallback() {                       // 插入 DOM 时
    this.innerHTML = `<button>0</button>`;
    this.querySelector('button').addEventListener('click', this.inc);
  }
  disconnectedCallback() { /* 清理 */ }
  static get observedAttributes() { return ['count']; }
  attributeChangedCallback(name, oldV, newV) { /* 特性变化 */ }
}
customElements.define('my-counter', MyCounter);
```

**核心概念清单**：
| 概念 | 要点 |
|---|---|
| Custom Elements | 标签名**必须带连字符**（`s-button` ✅，`sbutton` ❌） |
| 生命周期回调 | `connectedCallback` / `disconnectedCallback` / `attributeChangedCallback` |
| **attribute vs property** | attribute 是 HTML 上的字符串；property 是 JS 对象上的值。**复杂数据只能走 property** |
| Slot | `<slot name="primary-action">` 实现内容分发，对应 `<s-button slot="primary-action">` |
| Shadow DOM | 样式隔离。Polaris WC 用了它，所以**你的 CSS 改不到它内部** |
| CustomEvent | `this.dispatchEvent(new CustomEvent('change', { detail: {...}, bubbles: true }))` |

**为什么必须懂 Shadow DOM**：你会想"我给 `<s-button>` 加个 CSS 改颜色"，然后发现改不动。因为它在 Shadow DOM 里，外部 CSS 穿不进去。**只能用组件暴露的 CSS 自定义属性或 `::part()`。**

**Theme 线的用法**（Dawn 主题风格）：
```html
<product-form>
  <form>...</form>
</product-form>
<script>
  customElements.define('product-form', class extends HTMLElement { ... });
</script>
```
Theme 线没有构建工具，Web Components 就是它组织交互逻辑的方式。

### 学习资源
- [MDN Web Components](https://developer.mozilla.org/zh-CN/docs/Web/API/Web_components)（中文）
- 直接读 Shopify Dawn 主题的 `assets/*.js`，全是实战范例

# 7. HTTP / 网络 / 认证 🟠

> App 线的隐形大山。**很多人卡在这里不是因为不会 React，是不懂 OAuth 和 iframe。**

### 7.1 HTTP 基础
- 方法语义：GET（读，可缓存）/ POST（写）/ PUT / PATCH / DELETE
- 状态码：200 / 201 / 302 / 401（没身份）/ 403（没权限）/ 404 / 422 / 429（限流）/ 500
- 请求/响应头：`Content-Type`、`Authorization`、`Set-Cookie`、`Cache-Control`
- `Request` / `Response` Web 标准 API（React Router 7 的 loader/action 直接用它们）

### 7.2 CORS
跨域请求的规则、预检请求（OPTIONS）、`Access-Control-Allow-*`。
**Shopify 场景**：App proxy、Storefront API 从浏览器直连时会遇到。

### 7.3 Cookie 与 SameSite ⚠️
```
SameSite=Lax    默认，跨站不带 cookie
SameSite=None; Secure    跨站可带，但必须 HTTPS
```
**为什么重要**：嵌入式 App 在 iframe 里 = 第三方上下文。现代浏览器默认拦截第三方 cookie。这就是 Shopify 弃用 cookie session、改用 **session token** 的原因。

### 7.4 OAuth 2.0 安装流程
```
商家点安装
  → 跳到 Shopify 授权页（带 client_id, scopes, redirect_uri, state）
  → 商家同意
  → 回调你的 /auth/callback（带 code）
  → 你用 code 换 access_token（服务端，带 client_secret）
  → 存进数据库（Prisma session storage）
```
**模板已经帮你实现了**，但你必须理解流程，否则 debug 时完全抓瞎。

### 7.5 Session Token（嵌入式 App 的身份）
- 是一个 **JWT**，由 Shopify 前端签发，**1 分钟过期**
- App Bridge 自动附加到你的请求上
- 服务端用 API secret 验签
- **它只证明"这个请求来自某个商家的后台页面"**，不能直接调 Admin API
- 需要用 **Token Exchange** 换取 access token（模板已封装在 `authenticate.admin()` 里）

### 7.6 Webhook 与 HMAC 验签 ⚠️
Shopify 推事件给你时，header 里带 `X-Shopify-Hmac-Sha256`。
**必须验签**，否则任何人都能伪造"订单已支付"打给你的接口。
```ts
// 模板的 authenticate.webhook(request) 已经做了验签
const { topic, shop, payload } = await authenticate.webhook(request);
```
还要理解：webhook **至少一次投递**（可能重复），你的处理必须**幂等**。

### 7.7 CSP 与 iframe 嵌入
```
Content-Security-Policy: frame-ancestors https://admin.shopify.com https://<shop>.myshopify.com
```
返回错了 → Shopify 后台白屏。模板的 `boundary.headers` 就是干这个的。

# 10. Liquid 模板 🟡（Theme 线专属）

### 三大要素

```liquid
{{ 输出 }}          {% 逻辑 %}          | 过滤器
```

```liquid
{%- if product.available -%}
  <span>{{ product.price | money }}</span>
{%- else -%}
  <span>{{ 'products.sold_out' | t }}</span>
{%- endif -%}

{%- for variant in product.variants limit: 5 -%}
  {{ forloop.index }}: {{ variant.title }}
{%- endfor -%}

{%- assign sorted = collection.products | sort: 'price' -%}
{% render 'product-card', product: product %}     {# 引入 snippet #}
```

**`{%-` 里的连字符**是去空白，Dawn 到处都是。

### 核心对象
`product` `variant` `collection` `cart` `customer` `shop` `page` `blog` `article` `settings` `section` `block` `metafields`

### 常用过滤器
`money` `image_url` `img_tag` `escape` `t`（翻译）`default` `date` `handleize` `json` `where` `map` `sort`

### Online Store 2.0 概念
```json
// sections/featured.liquid 底部的 schema
{% schema %}
{
  "name": "Featured products",
  "settings": [
    { "type": "text", "id": "heading", "label": "Heading", "default": "Featured" },
    { "type": "collection", "id": "collection", "label": "Collection" }
  ],
  "blocks": [ { "type": "item", "name": "Item", "settings": [...] } ],
  "presets": [ { "name": "Featured products" } ]
}
{% endschema %}
```
理解：section / block / setting / preset / template JSON / app blocks。

### 关键限制
- Liquid 是**服务端渲染**，没有客户端状态
- 交互全靠原生 JS + **Ajax Cart API**（`/cart/add.js`、`/cart.js`、`/cart/change.js`）
- 有输出深度和循环次数限制

### 学习资源
- Liquid 参考：`shopify.dev/docs/api/liquid`
- **最好的教材是 Dawn 源码本身**：`github.com/Shopify/dawn`
- `shopify theme dev` 本地起服务，改文件实时同步

# 11. SSR / 边缘运行时 / 缓存 🟡（Hydrogen 线）

### 需要理解
- **SSR vs CSR vs SSG**：为什么电商必须 SSR（SEO + 首屏）
- **Hydration**：服务端 HTML + 客户端接管，以及 hydration mismatch 报错怎么排查
- **流式渲染**：`Suspense` + `<Await>` 让慢数据不阻塞首屏
- **Oxygen = Workers 运行时**（不是 Node）：
  - ❌ 没有 `fs` / `path` / `Buffer`（部分）/ `process`
  - ✅ 有 `fetch` / `Request` / `Response` / `crypto.subtle` / Web Streams
  - **后果**：很多 npm 包（尤其依赖 Node 内置模块的）装上会炸。选包前先确认 "edge/workers compatible"
- **缓存策略**：`CacheShort()` / `CacheLong()` / `CacheNone()` / `CacheCustom()`，以及 stale-while-revalidate
- **Storefront API 的 subrequest 缓存**
